Your coding agent reads less code to find the right file.

Nexus-MCP is a local MCP server for Claude Code, Codex, Cursor and any MCP client. The agent asks one question in plain words and gets the code back, instead of a tour of grep and file reads. Same answers, fewer tokens.

$ uvx --python 3.12 nexus-mcp-ci setup

Finds your MCP clients and asks before it writes. Not sure yet? Measure it on your own code first, free and offline.

How it works

  1. Index once

    The first call parses your code with tree-sitter and ast-grep, embeds each function and class with a local model, and stores it in .nexus/. A file watcher keeps the index current after each save.

  2. Ask in plain words

    search combines meaning and keywords. Its top results carry their whole code, so the agent does not open the file again.

  3. Follow the structure

    find_symbol returns the code of several names in one call, with callers and callees. graph gives the blast radius before a change.

What your agent gets

Five tools by default. Each one replaces several grep and read calls. The server tells the agent which tool answers which question when it connects.

search
"Where is", "how does". Hybrid search with the whole code of the top results.
find_symbol
Names you know. The code of each, with callers and callees. Long classes come back as an outline.
graph
Who calls this, and what breaks if it changes.
map
Layers, entry points and hub symbols of an unfamiliar repo.
index
The first call in a project. Incremental after that, multi-folder for monorepos.

Set NEXUS_EXTRA_TOOLS=all for memory (decisions that last across sessions), analyze (complexity and code smells) and status. Keep your agent's own grep for exact names you can type.

Call graph for Python, TypeScript, JavaScript, Go, Java, Rust, C, C++, C# and PHP. Search for 25+ languages.

Install in a minute

You need uv. Every route runs the same server.

$uvx --python 3.12 nexus-mcp-ci setup

Finds Claude Code, Codex, Cursor, VS Code, Cline, Windsurf, Gemini CLI and Claude Desktop, shows each change and asks first. --dry-run shows the changes only; --uninstall removes them. Or tell your agent: "Install Nexus-MCP from github.com/jaggernaut007/Nexus-MCP".

/plugin marketplace add jaggernaut007/Nexus-MCP
/plugin install nexus-mcp@nexus-mcp

The plugin registers the server and a short skill that tells the agent when to use each tool. Use the plugin or setup, not both.

Measure it on your code first

About 30 questions made from your project, Grep and Read against Nexus-MCP. Free, offline, no LLM. You get a verdict: Strong fit, Likely fit or Weak fit. On a tiny project Grep and Read win, and the report says so.

$uvx --python 3.12 nexus-mcp-ci eval

Your code stays on your machine

The server makes no network calls and has no telemetry. Two downloads come in once: the package and the embedding model. Nothing goes out unless you run one of two opt-in commands, and both ask first.

  • nexus-mcp-ci data where lists every stored file.
  • nexus-mcp-ci data clear removes them.
  • About 90 MB of memory idle, about 460 MB with the model loaded.

Questions

What is Nexus-MCP?

A local Model Context Protocol (MCP) server for AI coding agents. It indexes your code and answers questions about it with hybrid search, symbol lookup and a static call graph. The agent gets the code it needs in one call instead of a series of grep and file reads, so it uses fewer tokens. It runs on your machine and needs no API keys.

How do I test Nexus-MCP on my own code before I install it?

Run uvx --python 3.12 nexus-mcp-ci eval in your project folder. It compares Nexus-MCP with Grep and Read on about 30 questions made from your code, offline and with no LLM calls, and prints a verdict: Strong fit, Likely fit or Weak fit. For the real agent cost, nexus-mcp-ci eval --agent claude runs a paid A/B with your own Claude Code login after it shows the cost. The full guide.

Does Nexus-MCP lower token use for every project?

Not for every project. The saving is large on code the model does not know and small on code it knows from training, and on a tiny project Grep and Read win. The results table shows every repo we measured, including the ones where Nexus-MCP used more tokens.

Does my code leave my machine?

No. Parsing, embeddings and the index all run locally. Nexus-MCP sends no code to any service, has no telemetry and needs no API keys. The embedding model downloads once; set NEXUS_OFFLINE=1 after that. Only the opt-in eval --agent and eval share commands send anything, and both ask first.

Which agents and languages does it work with?

Any MCP client that supports the stdio transport, including Claude Code, Claude Desktop, Codex, Cursor, VS Code, Cline, Windsurf and Gemini CLI. Search, symbols and the call graph cover Python, TypeScript, JavaScript, Go, Java, Rust, C, C++, C# and PHP. Search covers more than 25 languages.

How does Nexus-MCP compare with Serena and claude-context?

Serena finds code through language servers and can edit code. claude-context runs hybrid search over a vector database with an embedding provider. Nexus-MCP is read only and fully local: hybrid search in a local index with a local embedding model, and a static call graph for ten languages. Measure it on your own repository with nexus-mcp-ci eval instead of relying on any comparison. Feature table.
